1. Рабочая папка содержит текущие файлы, индекс содержит подготовленные к коммиту изменения, репозиторий хранит историю коммитов.
2. git add добавляет изменения в индекс. git commit сохраняет изменения в новый коммит. git push отправляет коммиты в удаленный репозиторий.
3. Информативные сообщения помогают понять, какие изменения были сделаны, и облегчают поиск нужных коммитов в истории.
4. git add имя_файла добавляет только указанный файл. git add . добавляет все изменения в текущей папке. Первый вариант удобен для точечного добавления, второй для добавления всех изменений.
5. git status показывает состояние файлов и индекса: измененные, новые и подготовленные к коммиту файлы.
6. git remote add origin URL связывает локальный репозиторий с удаленным. origin это стандартное имя удаленного репозитория.
7. Флаг -u связывает локальную ветку с удаленной, чтобы в дальнейшем можно было использовать git push и git pull без указания ветки.
8. Ветка по умолчанию это основная ветка репозитория. Обычно сейчас используется main, а в старых репозиториях может быть master. Это важно, потому что именно с ней обычно связана основная история проекта.
9. Историю можно посмотреть командой git log. Для каждого коммита отображаются его идентификатор, автор, дата и сообщение.
10. Изменения не попадут в коммит, потому что git commit сохраняет только изменения, добавленные в индекс с помощью git add.
